# 브랜치 · PR · 커밋 컨벤션

모든 레포(`frontend` / `backend` / `ai` / `docs`)에 공통으로 적용합니다.

## 브랜치

| 브랜치 | 용도 |
| --- | --- |
| `main` | 최종 데모 · 배포 |
| `dev` | 개발 통합 |
| `feature/기능명` | 기능 작업 (예: `feature/growth-record`) |
| `fix/버그명` | 버그 수정 (예: `fix/login-redirect`) |

- `main`, `dev`에는 직접 push하지 않습니다.
- 작업은 항상 `dev`에서 브랜치를 따서 시작합니다.

## PR

1. `feature/*` → **`dev`** 로 PR을 올립니다.
2. 본문에 **무엇을 했는지**와 **영향받는 부분**을 한두 줄로 적습니다.
3. 팀원 1명 이상 확인 후 merge합니다.
4. API 응답 형식처럼 다른 파트에 영향이 가는 변경은 해당 파트 담당을 리뷰어로 지정합니다.
5. 발표 전 `dev` → `main`으로 merge합니다.

## 커밋

`타입: 작업 내용` 형식으로 작성합니다.

| 타입 | 의미 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `style` | 디자인 · CSS 수정 (로직 변경 없음) |
| `refactor` | 코드 구조 개선 |
| `docs` | 문서 수정 |
| `chore` | 설정 · 패키지 설치 등 |

예시: `feat: 자립 성장 기록 페이지 추가`
